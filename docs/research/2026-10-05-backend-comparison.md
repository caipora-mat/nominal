## Recommendation and decision boundary

Prefer a staged hybrid: a command checks a restricted binding schema, generates
ordinary raw inductive declarations and alpha quotients for each declaration
block, and builds their public interfaces using a shared library of verified
semantic certificates. Initially share arity interpretation, coherent actions,
support/freshness arguments, abstraction descent, and induction/recursion proof
components. Extract broader shared theorems when two generated clients expose
the same proof obligation. Kernel-check every generated declaration.

A normalized signature is useful metadata even when it is not interpreted as
one universal syntax type. The initial architecture need not choose a generic
raw carrier. Equally, ordinary inductives are an implementation device, not a
promise that the public alpha quotient has Lean's unrestricted inductive
recursor or definitional constructor computation.

This recommendation is a research inference from the current case study and
the bounded probes below. No proof currently shows that the proposed restricted
grammar supports the complete generated interface. The earliest mathematical
gate is a hand-checked mutual, nested-binding example using that exact grammar,
followed by generated lambda and first-order logic clients. The agreed later
portfolio adds lambda calculus with let, pi calculus, and mu calculus;
the user selected let over imperative locals. Positive modal mu calculus is a
proposed specialization, whose exact semantics remains to be selected. These
are validation stages, not evidence that their judgment rules already fit
a generic fresh-induction theorem.

## A precise candidate grammar

The following is a proposed first accepted grammar, not an already implemented
DSL or a claim to accept every first-order language.

Choose one atom type `A : Type u` with `Name A`, a finite nonempty set `I` of
syntactic categories, finitely many external data parameters `D_k : Type u`
with explicit nominal structures, and finitely many constructor labels. Each
constructor has one result category and one arity generated by:

```text
S ::= Unit | Atom | Data(k) | Rec(i) | S × S | Bind(S)
```

Constructor labels and category indices are fixed discrete metadata. Interpret
the arity relative to a family of already existing nominal carriers `X_i`:

```text
Unit       ↦ PUnit                         Atom    ↦ A
Data(k)    ↦ D_k                           Rec(i)  ↦ X_i
S × T      ↦ ⟦S⟧ X × ⟦T⟧ X                 Bind(S) ↦ NameAbs A (⟦S⟧ X)
FΣ(X)_i    ↦ coproduct over constructors returning i of their arities
```

`Atom`, `Data(k)` and `Rec(i)` have distinct roles. An atom is an occurrence of
a name; a recursive position is a child of the declared category; an external
data value is opaque nominal data with the explicitly selected action. A
recursive map acts as identity on atoms and external data and maps recursive
children. Permutations still act on every atom and nominal data value. Ordinary
discrete labels, integers or symbol names require explicit discrete structures
or wrappers; a type's being usable as data does not prove that an arbitrary
operation on it is equivariant or supported.

`Bind(S)` binds exactly one atom throughout its enclosed arity, including name
occurrences and support inside external nominal data in that arity. It does not
scope over neighboring constructor arguments. Thus a nonrecursive let has
arity `Rec(term) × Bind(Rec(term))`: the right-hand side remains outside scope.
`Bind(S × T)` intentionally shares one binder across both components. Nested
`Bind(Bind(S))` gives ordered, nested single binders, with ordinary alpha
renaming and possible vacuity/shadowing. Binder annotations are lexical scope
descriptions, not just names placed next to arbitrary fields.

The shared-scope product is useful for a pi-calculus bound residual containing
both a label and a continuation. It does not introduce unordered, simultaneous,
set, pattern, or generalized binders. Their equality and vacuity conventions
would require separate specifications.

| Shape or feature | First grammar decision | Reason or condition |
| --- | --- | --- |
| Finite tuples, nullary constructors | Accept | Products and `PUnit` |
| Multiple categories and mutual recursion | Accept as the target grammar | Finite category-indexed inductives or generated mutual blocks; all references strictly positive |
| Recursive occurrence in a function domain | Reject | Fails positivity; no function-space arities in this grammar |
| Recursive `NameAbs A T` as a Lean constructor field | Reject as a construction method | Circular nominal-instance requirement and independent kernel obstruction, reproduced below |
| `List (Rec i)`, `Option (Rec i)`, `Array`, `Finset`, arbitrary container applications | Reject direct container syntax initially | Each extension needs map, relation/predicate lifting, induction and binder interaction; kernel positivity alone is insufficient |
| Auxiliary user-declared list category | Accept | Constructors `nil : Unit` and `cons : Rec i × Rec list` use the stated grammar |
| Fixed finite alternatives | Express as distinct constructors | Constructor coproduct is already part of the signature |
| Containers with no recursive occurrence | Accept only as external `Data(k)` | A supplied nominal structure is required; package does not inspect their elements |
| Dependent arities, indexed public families, type-changing/nonuniform recursion | Reject initially | Would change the induction and interpretation contract |
| A new category used by an earlier one | Accept in the same checked block | Does not require another atom sort |
| A second atom sort or a second independent binding namespace | Reject initially | Current `outParam` inference is not a multiple-sort design |

Rejecting direct `List`/`Option` syntax is a scope choice, not a mathematical
impossibility claim. Optional elaborator sugar can later lower a finite shape to
this grammar with proved public isomorphisms. Do not silently translate a
user-supplied container and assume its usual eliminator or equality is preserved.
Variable-length function-symbol arities encoded by dependent vectors are outside
this first grammar; the FOL case study must choose fixed-arity symbols or an
explicit auxiliary list category.

All atom, carrier, external-data and binder-elimination result types initially
share `Type u`, matching current `NameAbs`, quotient and FCB interfaces. Unit
and empty shapes use `PUnit` and `PEmpty` at that universe. Arbitrary mixed
universes are deferred; explicit lifts are possible but need action/operation
transport proofs. The probe is universe-polymorphic in this shared `u`, rather
than solving the issue by restricting all syntax to `Type 0`.

## Three backend choices

| Criterion | Generic signature and raw alpha quotient | Proof-producing per-declaration generator | Staged hybrid recommendation |
| --- | --- | --- | --- |
| Representation | One category-indexed carrier interpreted from the signature | Separate generated raw inductives, alpha relations, quotients | Separate carriers initially, shared binding metadata and semantic certificates |
| Main trusted input | Ordinary kernel plus proved generic core | Ordinary kernel; generated proofs are checked | Same; certificate fields are proved, never postulated |
| Mathematical work | Prove generic carrier, alpha theory, constructor interface, fresh induction and recursion once | Reproduce proof templates for each accepted declaration shape | Prove reusable local theorems and transport interfaces, with declaration-specific structural proofs |
| Frontend work | Generate aliases, constructors, names and readable specialized principles | Elaborate inductives, prove relation/action/quotient laws, generate useful principles | Normalize grammar, generate raw structure and fill a stable theorem contract |
| Main usability risk | Interpreted sums/indices/casts leak into rewriting, errors and motives | Large or brittle generated proofs, duplicated mathematical arguments | An underspecified certificate hides a hard obligation; excessive transport burdens simplification |
| Main scope risk | General generic theory grows before the function/judgment workflow exists | Template accepts shapes for which alpha or refreshment proof fails | Shared core gradually becomes a second competing representation unless boundaries stay explicit |
| First feasibility gate | Actual generic alpha quotient and nontrivial mutual example | Generated two-category example with all theorem proofs | Manual certificate for two-category syntax, then generator consumes the same interface |

The alternatives can implement the same user grammar without having equivalent
internal proof costs. No equivalence of these architectures has been proved.
A generic interpreter *alone* is not a generic recursive syntax carrier. In
particular, writing `inductive T where node : F(T) → T` does not bypass Lean's
positivity or instance requirements when `F` includes semantic abstraction.

Raw syntax is a well-supported construction route, demonstrated by the existing
lambda implementation. It is not a mathematical necessity theorem. A verified
initial-chain/colimit construction is an alternative; it owes the actual
colimit and preservation arguments, universe bookkeeping, constructor laws,
and useful induction/recursion principles. Binary product/sum isomorphisms do
not establish preservation of the required omega-chain colimit. Calling the
colimit an omega-stage fixed point should not suggest that some finite stage of
the sequence stabilizes. Another alternative could use a canonical nameless
representation, but would need nominal actions, correspondence and the same
fresh public interface; no such construction was investigated here.

## Staging, alpha theory and action coherence

A concrete dependency order for the hybrid is:

1. Check the finite categories, external nominal parameters and binding scopes.
2. Generate ordinary raw inductives with explicit binder-atom fields. Generate
   structural permutation action and finite-support evidence on these raw types.
3. Define mutually compatible alpha relations and prove equivalence,
   constructor congruence, equivariance and size/rank invariance.
4. Form the quotients and inherit the canonical action from the proved
   equivariant relations. Never accept an unrelated nominal structure merely
   because it inhabits the same carrier type.
5. Define public constructors; prove disjointness and equality/injectivity in
   terms of the semantic arities. Only now use `NameAbs` on recursive quotient
   carriers. Its body already has a nominal instance.
6. Prove constructor support equations, representative refreshment, arbitrary-
   predicate strong induction, supported iteration and its equations/uniqueness.
7. Provide the separate primitive-recursion and judgment-definition contracts;
   do not infer them solely from successful iteration.

Exact quotient support is an obligation, not a corollary of its generic upper
bound. Raw support contains binder atoms; quotient support deletes them.
Likewise, a generic arbitrary-motive induction theorem needs actual recursive
hypotheses. Under a semantic abstraction, selecting one body and asserting an
arbitrary `P body` is generally representative-dependent. A construction can
instead reason over raw representatives and strengthen over permutations and
contexts, as current lambda induction does; a semantic lifting must explicitly
quantify the required representatives or otherwise prove well-definedness.

The intended public family of motives is unrestricted
`P_i : T_i → C → Prop`, for a nominal avoidance context `C`, with recursive
hypotheses generalized over contexts and chosen binders fresh for the current
context. No support certificate for `P_i` is implicit in this contract. Mutual
and nested scopes need coherent fresh choices; this theorem has not been proved
generically by the raw-type probe.

The existing `PermType` and `Nominal` atom parameters are `outParam`s. Generated
types must carry enough parameters to select their one intended atom action;
avoid duplicate nominal structures and independent competing `SMul` instances.
For signature *interpretation*, return a bundled carrier with its nominal
structure at each recursive step. The successful `BackendProbe.interp`
experiment demonstrates this local repair of the historical circularity.
Bundling an interpreter does not solve recursive carrier construction.

## Abstraction, functions and the exact universal property

Reuse current interfaces in this order:

- `NameAbs` gives binder equality, same-binder injectivity, exact support deletion
  and fresh/common representatives once bodies are nominal.
- Concretion gives observation at a fresh atom and reconstruction. It does not
  supply an equivariant chosen representative or unrestricted binder-extraction
  operation. Existing `concreteAt` is partial; fresh-domain facts justify use.
- `liftAbs` maps an **equivariant** function through abstraction, with map laws.
- `NFun` packages finitely supported functions and supports parameters,
  currying, composition and higher-order use under the conjugation action.
- FCB and `liftFCB`/`liftFreshParam` justify descent of binder handlers. The
  current FCB has cofinite totality/freshness uniform in the body, with equation
  hypotheses stated by its public theorems; it is not unrestricted quotient
  elimination for arbitrary handlers.

For a supported map `f`, an enriched abstraction map should satisfy
`mapAbs f (abs a x) = abs a (f x)` when `a # f`, together with support, action,
identity and composition laws. The unguarded equation is false: let the body
type be discrete Unit and `f` constantly return `c`. Then `abs c () = abs b ()`
for any `b`, but `abs c c ≠ abs b c` when `b ≠ c`. This counterexample is
proved in `BackendCounterexamples.no_unconditional_const_abs_map`.
The counterexample rejects the unconditional equation, not the enriched map;
FCB/parameterized fresh elimination is the plausible construction route.
The old `liftAbs_NFun` is only a stub, not available generic infrastructure.

If initiality is included, state it in a specified category. For the arity
functor `FΣ` on the category `Nom_A^I`, use componentwise **equivariant** maps.
An algebra is `(Y, h : FΣ Y → Y)` with equivariant `h`. The proposed term
algebra is `(T, in)`, with equivariant constructor map. For each algebra require:

```text
there exists exactly one family f_i : T_i → Y_i of equivariant maps such that
f_i (in_i x) = h_i ((FΣ f)_i x)             for every i and x.
```

Functor maps and their identity/composition laws must already be proved.
If a constructor isomorphism is exported, its forward function must equal
`in`, with both inverse laws; a separately chosen type equivalence is not this
claim. Initiality in equivariant maps does not establish iteration for arbitrary
fixed supported handlers. Prove a supported/enriched extension with its support
and binder equations, or derive a parameterized construction through a nominal
function carrier with proved handler admissibility.

Iteration gives handlers only recursive results. Primitive recursion must also
provide original quotient subterms, for example by a proved iteration into
products `(original, result)` and a reconstruction invariant. Under binders,
those originals and results must be kept in the *same* abstraction scope; their
freshness/descent obligations do not disappear by forming a product. Fully
type-valued dependent elimination is another contract, requiring transport and
coherence, and is not promised by either iterator or arbitrary-`Prop` induction.

## Bounded Lean evidence and remaining gates

These commands were run successfully against the existing built imports and
unchanged pinned Lean/Mathlib 4.34.1:

```sh
lake env lean docs/research/probes/BackendPositivity.lean
lake env lean docs/research/probes/BackendStaging.lean
lake env lean docs/research/probes/BackendCounterexamples.lean
```

- [BackendPositivity.lean](probes/BackendPositivity.lean) checks three expected
  failures with `#guard_msgs`. Direct recursion through `NameAbs` fails to
  synthesize `Nominal α (Direct α)`. Supplying an explicit discrete structure
  reaches the separate kernel error: the recursive constructor argument
  contains a non-valid datatype occurrence. A minimal `Quot` wrapper exhibits
  the same kernel rejection without nominal machinery. This is evidence about
  the tested encodings, not a theorem excluding every quotient-based carrier.
- [BackendStaging.lean](probes/BackendStaging.lean) proves the staged interpreter
  is accepted, including products, nested abstraction and a shared arbitrary
  universe. A category-indexed raw term/formula type has recursive references
  in both directions, explicit single binders, ordinary induction, and proved
  map identity/size invariance. It does not prove its alpha theory or nominal
  structure, or generically generate syntax.
- [BackendCounterexamples.lean](probes/BackendCounterexamples.lean) proves the
  two function counterexamples above using current public APIs.

All printed positive-result axiom lists contain only `propext`,
`Classical.choice`, and `Quot.sound`, or a subset. No admissions or custom axioms
were added. Initial ad hoc probes in `/tmp` were used to discover diagnostics;
the persistent negative probes guard the expected failures and exit successfully.
No full-library rebuild or clean dependency bootstrap was needed or performed
for these documentation/scratch additions.

The Lean reference explains ordinary, mutual and nested inductive construction
and its positivity constraints; the local pinned probes are the evidence for
the exact acceptance/rejection behavior reported here.
[Lean reference: inductive types](https://lean-lang.org/doc/reference/latest/The-Type-System/Inductive-Types/)
(accessed 2026-10-05; rolling documentation, not pinned to the compiler release).

Before implementation commits to the hybrid, require a manual two-category
certificate with constructor equality/support, a binder over a product, nested
binders, arbitrary-motive fresh induction, supported parameterized iteration,
and a definition whose bad binder handler is rejected. Then require a generated
client consuming each theorem and a separate derivation-induction certificate.
Raw positivity, alpha compatibility, function support and rule refreshment are
four different gates; passing one must not silently stand in for the others.
